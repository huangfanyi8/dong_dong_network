# dong-dong-learning

本项目学习方法与知识验收标准。配合 `dong_dong_network_requires_v1.md`（要做什么）与 `AGENTS.md`（怎么协作）使用。

## 三条铁律

1. **问题驱动**：不预讲概念。先写能跑的代码 → 跑出问题 → 讨论痛点 → 引入解决方案（新概念）。每个新概念都能回答"它解决哪个具体问题"。
2. **反问模式**：每完成一个目标，学习者必须用自己的话回答问题，禁止背概念；答错就回到代码与痛点重走，不批评。
3. **以目标为单位**：完成一个目标（编译+验证+反问通过）才提交，一目标一提交一 PR，不跳步。

## 目标完成流程

```
① 目标回顾 → ② 讲解痛点+读参考 → ③ 写代码 → ④ 编译+验证 demo → ⑤ 反问确认 → ⑥ 提交 git + 推远端 + 开 PR
```

## 反问细则

- 时机：每个目标代码验证通过后、进入下一个目标前。
- 形式：agent 按 requires v1 该目标的反问清单提问，学习者口头/文字用自己的话回答。
- 判定：通过 → 进入下一目标；答不出/含糊 → 一起回到代码重新走一遍，重试。
- 加分项：学习者在 muduo 参考代码中指出对应实现（文件名）。

## 验收清单（每目标结束自检）

- [ ] 能用大白话讲清"当前痛点 → 引入的方案"因果链
- [ ] 能画出涉及的关键流程（如 EventLoop::loop 循环）
- [ ] 能在 muduo 参考代码中定位到对应实现
- [ ] 清楚该方案的局限（为下一步埋下的问题）

## 读 muduo 参考的方法

- 每步先自己写，写完再对照 muduo 看它怎么做的、为什么那样做。
- `muduo/`、`test/`、`spdlog/` 不参与构建、不改动，仅作参考。
- 对照重点：接口为什么这么设计、事件回调怎么组织、生命周期谁负责。
